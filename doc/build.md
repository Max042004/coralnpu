# Building CoralNPU with Bender + Make

This replaces the former Bazel build. The tools split the work the same way
OpenHW/PULP projects do:

| Concern | Tool | Files |
|---|---|---|
| Third-party RTL, file lists | [Bender](https://github.com/pulp-platform/bender) | `Bender.yml`, `vendor/`, `vendor/patches/` |
| Chisel → SystemVerilog, Chisel unit tests | sbt + firtool | `build.sbt`, `project/`, `hdl/chisel/src` |
| Orchestration | GNU Make | `Makefile`, `mk/designs.mk` |
| Reproducible environment | OrbStack Linux VM | `utils/setup_vm.sh` |

## Environment (OrbStack)

Build inside an Ubuntu 22.04 x86_64 OrbStack machine; it sees the macOS
checkout directly, so edit on the Mac and build in the VM:

```bash
orb -m vivado -w "$PWD" bash utils/setup_vm.sh      # once: bender, sbt, firtool, verilator
orb -m vivado -w "$PWD" env PATH="$HOME/bin:$PATH" make rtl DESIGN=CoreMiniAxi
```

`setup_vm.sh` pins Bender, sbt, firtool (`llvm-firtool` from Maven, same
version as the old Bazel build) and Verilator 5.052 under `~/tools`.

## Third-party RTL

`common_cells`, `fpu_div_sqrt_mvp`, `cvfpu` and `RVVI` are declared as
`vendor_package` entries in `Bender.yml`, pinned to the same commits as before.
The patched result is committed under `vendor/`; the patch series live in
`vendor/patches/<pkg>/` and are applied with `git apply`. To bump a revision
or change a patch:

```bash
make vendor-update
```

Chisel BlackBoxes still find these files as classpath resources
(`external/cvfpu/...`, `hdl/verilog/...`); `build.sbt` stages them from
`vendor/` and `hdl/verilog/`, so the Scala sources are unchanged.

## Generating RTL

```bash
make list-designs
make rtl DESIGN=VmeCoreMiniAxi       # -> build/rtl/VmeCoreMiniAxi/VmeCoreMiniAxi.sv
make rtl-all
```

`mk/designs.mk` holds the generator class and flags for every design (it was
extracted from the former `chisel_cc_library` targets).

## Tests and file lists

```bash
make chisel-test T=coralnpu.AluSpec   # one test class; omit T for everything
make flist                            # build/coralnpu.f from Bender.yml
```

## Verilator models, firmware and cocotb

```bash
make list-models
make model MODEL=core_mini_axi_model            # Verilate (generates the RTL first)
make elfs-cocotb                                # firmware for tests/cocotb (make list-elfs)
make riscv-tests                                # riscv-tests ELFs (vendored, patched)
make cocotb-suite SUITE=tests_cocotb_core_mini_axi_sim_cocotb
make cocotb-test MODEL=core_mini_axi_model MODULE=tests.cocotb.core_mini_axi_sim TESTCASE=core_mini_axi_slow_bready
```

* `mk/models.mk`, `mk/sw_targets.mk`, `mk/cocotb_suites.mk` are tables extracted
  from the former Bazel targets by `utils/extract_*.py` (kept for regeneration
  while Bazel files still exist).
* Firmware uses the prebuilt toolchain (`utils/setup_vm.sh toolchain`) and
  `utils/gen_linker_script.py` (port of `rules/linker.bzl`). `SW_COPT=opt|dbg`
  selects the optimisation mode (default is Bazel's `fastbuild`).
* The tests are unchanged: `utils/pyshim/` provides a stand-in for
  `bazel_tools.tools.python.runfiles` that resolves `coralnpu_hw/<path>` in
  `build/runfiles/` (built artifacts) and then in the source tree.
* `utils/cocotb_run.py` replaces `rules/cocotb_wrapper.py`.

Verified on the `vivado` OrbStack VM: `core_mini_axi_sim` passes 30/30 on both
`core_mini_axi_model` and `rvv_core_mini_axi_model`; a TL-UL suite also passes.

## Firmware libraries

`mk/sw_targets.mk` is generated by `utils/extract_sw.py`, which *executes* the
Bazel BUILD files with stub rules (macros, comprehensions and `template_rule`
expand exactly as in Bazel). It covers 749 firmware targets, including the RVV
template tests (`mk/gen_sources.json`, expanded by `utils/expand_templates.py`),
FreeRTOS (vendored) and TensorFlow Lite Micro (`libtflm.a` from the source list
in `mk/tflm_sources.mk`, model arrays via TFLM's `generate_cc_arrays.py`).

## Host-side C++: Spike, SystemC, MPACT

Large unmodified dependencies are not vendored; `tools/Bender.yml` pins them
(abseil, SystemC, libsystemctlm-soc, pybind11, antlr4, ELFIO, linenoise):

```bash
make host-deps absl systemc antlr4     # fetch with Bender, build with CMake
make spike spike-test                  # patched riscv-isa-sim + co-sim wrapper tests
make sim SIM=core_mini_axi_sim         # Verilator/SystemC testbench (make sim-list)
make sim-tests hwsim                   # other testbenches, libcoralnpu_simulator*.so
make mpact mpact-pytest                # MPACT ISS + python binding tests
```

The MPACT stack (mpact-sim, mpact-riscv, coralnpu-mpact; vendored and patched)
keeps its Bazel build graph as the source of truth: `utils/bazel2make.py`
executes the BUILD files and emits `mk/mpact_rules.mk` plus one script per
genrule in `mk/mpact_cmds/` (ISA/bin-format decoder generation, ANTLR). Re-run it
after changing the vendored revisions:

```bash
python3 utils/bazel2make.py @coralnpu_mpact//sim:coralnpu_simulator @coralnpu_mpact//sim:coralnpu_v2_sim @coralnpu_mpact//sim/cosim:coralnpu_cosim_lib
```

Verified on the `vivado` OrbStack VM: Spike wrapper tests (16), MPACT
`coralnpu_v2_sim_test` (15), `core_mini_axi_sim` on a firmware ELF,
`core_mini_axi_non_incr_tests`, `backdoor_load_test`, `dbus2axi_tb`.

## FPGA SoC and UVM

```bash
make fpga-deps                                   # pinned OpenTitan + ISP sources
make chip-verilator VARIANT=vector_normal        # full-chip Verilator model (4 variants)
make fpga-sim-tests                              # clk / trivial_pass (SPI loader) / dma / highmem
make chip-nexus VARIANT=vector_normal TYPE=elab_only|synth_only|bitstream
make uvm-model [DUT=rvv|vme]                     # UVM testbench on Verilator (+ MPACT, Spike DPI)
make uvm-test ELFS="tests/cocotb/wfi_slot_0" [SPIKE=1]
make uvm-regression [SPIKE=1]                    # 821 firmware / riscv-tests ELFs
```

The SoC embeds OpenTitan IP whose cores are FuseSoC-native, so `fusesoc` is still
used to resolve the file sets (and to drive Verilator/Vivado through edalize);
Bender and make own everything around it: pinned downloads, the generated Chisel
subsystem core, the search path and the flags (`mk/fpga.mk`). The VCS flavours of
the UVM bench need a Synopsys licence and are not built here.

Known upstream problems in this snapshot (reproduced, not introduced by the port):

* `fpga/rom_test*` (ROM-boot images) do not link: `fpga/sw/rom_boot/crt0.S` uses
  `_stack_top`, `_data_load`, ... that neither `rom.ld` nor `rom_highmem.ld` define.
  The ROM boot variants of the SoC therefore have no working image.
* `coralnpu_soc.sv` instantiates `CoralNPUChiselSubsystem`, while the Chisel
  emitter names the matrix/highmem subsystems after their configuration; the make
  flow renames the top module when it stages the generated core.

## Status of the migration

Done: RTL dependency management, Chisel generation and unit tests, tool
provisioning, Verilator cocotb models (60 of 65 suites pass), firmware
(757 targets), riscv-tests, FreeRTOS, TFLite Micro, Spike, SystemC testbenches,
hw_sim shared libraries, MPACT and its python binding, FPGA SoC Verilator flow
and simulation tests, UVM Verilator regression (821 ELFs pass).

Not verified: Vivado builds (the VM's Vivado 2019.2 lacks the xcvu13p device;
the FuseSoC project setup itself works), VCS flows (licence), the `*_slow`
cocotb suites, `mobilenet_v1`.

Still on the former Bazel rules: lint, CI, npusim example runner, and the Bazel
files themselves.
